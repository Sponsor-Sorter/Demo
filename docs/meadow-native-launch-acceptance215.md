# Meadow Markets native launch acceptance

Prepared31October2026. This is an execution checklist, not a completed device test. The human has paused Samsung use; browser acceptance does not replace these checks.

## Entry and farm preservation

1. Wait for an explicit release of the idle Samsung. Record installed package/version, distribution, Android version, orientation and available storage. Do not interrupt Frontlines or another test.
2. Confirm the current farm has a ready Meadow Markets username and a recovery method privately saved by the human. Confirm the latest cloud revision; privately export a farm backup. Record balances and owned items as acceptance evidence, without passwords, recovery keys, session tokens or purchase tokens.
3. Test a small reversible action and reload in the existing installation. Confirm that exact cloud account returns. Keep the reviewer account unchanged while Google reviews it.
4. Join the existing Play internal track with the licensed Google tester account. A Google tester login and a Meadow Markets farm login are separate accounts. Install only from the verified Play listing.
5. The direct APK and Play builds may have different signing certificates. If Android rejects replacement, stop: preserve the working installation and obtain the human's approval for any uninstall after recovery is proven. Do not resolve a signature mismatch by silently wiping the app.
6. After installing, sign into the same farm and compare account, balances, buildings, gems and receipt ownership. Native10 loads the current website content. Confirm Play updates through Play, while remote game updates retain the in-game prompt.

## Isolated provider acceptance

Keep public payments/ads off and all seven product options inactive until an explicitly documented test configuration is ready. Current free tester packs exercise game receipts; they do not exercise Google Billing. The native test-AdMob IDs do not prove the live SSV path.

Before an actual Billing test: configure a Google license tester and a dedicated registered protocol4 farm with recorded provenance. Scope any temporary provider access to that account and Google test payment methods; do not enable general customer checkout. Confirm the Google sheet explicitly identifies a test transaction before confirming it. Store raw provider tokens only in the private backend.

| Flow | Required result / evidence |
|---|---|
| Prices and entry | Localized Play prices; guest/incomplete/legacy farms cannot start paid checkout. No web checkout for Android digital goods. |
| Cancel | Cancel the Google sheet; no wallet, receipt or inventory change. Controls recover. |
| Pending | A pending test payment gives no items. Completion later verifies the original purchase once. |
| Consumable | One small test gem purchase: account-bound server receipt, exact gem amount, token settled only after delivery. Retry/rotation/reload cannot duplicate it. |
| Lost reply | Interrupt after Google success; Restore retries the same purchase. Exactly one delivery and no second charge. |
| Premium / restore | One non-consumable test purchase; restore on the purchasing farm after relaunch. Wrong farm cannot receive the benefit. Premium suppresses optional popup ads. |
| Refund | Use the provider's authorized test refund/revoke path. Authenticated RTDN maps the recorded token to its owner, removes the benefit once and applies the documented review hold. Duplicate/out-of-order notifications do not re-credit. |
| Consent | UMP geography debug only on the test device. Test accept, reject, manage choices, reset/reopen, landscape and portrait. Rejecting optional consent must still allow farming. Remove debug overrides before release. |
| Ads unavailable | Offline, no-fill and load failure return to gameplay, with no stuck overlay, timer penalty or unearned reward. |
| Rewarded ad | Player opts in; one issued nonce and provider-verified callback grant one reward. Closing early grants none. Forged/replayed callback grants none. Record callback status/receipt ID, not raw signed URLs or credentials. |
| Interstitial | Natural break only, respects frequency cap, consent and premium. No popup during an active game gesture or purchase. |

Until that isolated provider configuration and the Play/AdMob app eligibility are confirmed, mark provider rows **pending**, not passed. Never use ordinary billable payment methods to simulate a license test.

## Device gameplay and reliability

- Exercise portrait, both landscape directions, rotation during a popup and the Android safe areas. Inspect compact HUD, roster/build scrolling, long hold versus camera pan, pinch zoom, release-to-place, details/move/rotate/sell and popup return controls.
- Play one crop cycle, one animal care/collect flow, one production queue and one premium market sale. Upgrade a queue and well: the open window must show the acknowledged saved state immediately.
- Leave an assigned hired worker on another map. Verify till/plant/water/harvest and production jobs use that farm's well, caps, gold and crop choice. Inspect live roster status and the worker sprite on return.
- Accept a remote game update, then relaunch offline. Confirm the exact installed start document opens from cache; reconnect and verify no duplicate rewards or lost pending commands.
- Force-close during a pending action and reopen. The original immutable request retries; it must not create a replacement action or upload an old snapshot.
- Run a heavy farm for15minutes, including map travel and a fullscreen game. Record frame-time distribution, long tasks, memory trend, network requests and battery/thermal behaviour. Compare the same scene before/after any fix; a build success is not a performance result.
- Check low-memory/relaunch, intermittent network and a second browser view of the same QA farm. Resolve stale revisions explicitly; never duplicate resources.
- Test storage exhaustion only through a reversible scoped QA method, without filling the user's disk or deleting their files. A failed local checkpoint must keep the pending receipt and explain recovery. Do not evict another app's caches.
- Repeat layout/touch and installed-web/offline checks on a physical iPad when available. A browser viewport is only a responsive-layout check.

Return temporary provider controls to off, remove debug ad/consent overrides, retain private evidence and remove only the disposable QA account after its session is ended. Record each row as passed/failed/pending with build, device, time and evidence. Obtain final activation review only after the production gates pass; then verify Google review/public installation and AdMob app-store linking separately.
