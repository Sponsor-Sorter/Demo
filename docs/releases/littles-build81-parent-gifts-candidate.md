# Littles 81 gift consumer candidate

Prepared in `codex/littles-gifts81` from `5ae39beb9f3207f7a652510f3ce90a6d97d0ce02`. This is an isolated review candidate. It has not been pushed, published, enabled or tested on the phone. Learning80 is independently accepted and live; its phone reservation has been released.

Grown-up Settings gains a gift-code form at quality81. A plain code such as `live2026` needs no prefix, ignores ASCII spaces/hyphens and accepts either case. Non-ASCII input is rejected before case conversion. The form uses the existing parent gate, paper surfaces and separate controls of at least44CSSpx.

The consumer first refreshes normal verified-parent Play status, which creates the normal account binding, then calls the frozen Fairplay gift status/redemption RPCs for `littles`. Only timed `littles_plus` is supported. It never grants stars, alters a paid receipt or unlocks from a complimentary-grant UUID.

The initiating parent UID and auth generation are captured before any await. Actor and session lookups are fenced before sending; the RPC uses that session's captured bearer so a later SDK token lookup cannot select another account. Responses are fenced again. Bearers are absent from the public gift identity, logs and new storage. Only app/code/request are sent; recipient and reward authority stay on the server.

A request UUID is retained in memory for the same account/session/normalized code after an uncertain result. Double taps cannot send two requests. Closing or re-rendering clears the input and listeners while allowing a safe same-session retry. An accepted receipt triggers ordinary RSA-verified Plus refresh; access stays locked while verification is pending. Proof retry does not redeem again. Expired previously redeemed gifts are described as expired even if another Plus source is active.

Validation: dedicated normalization/controller and captured-bearer transport tests; existing commerce, account and recovery suites. Four isolated browser sizes cover the real parent gate, lowercase code, pending state without proof, RSA-verified activation, cleared input and separate44px controls. All browser transport and accounts are local fixtures; no real code was issued or redeemed.

Before any gift rollout: Root must approve the exact candidate; coordinate a new private81 publication and phone window, inspect the actual installed-app parent panel with the catalogue still off, then qualify/test solely on disposable actor `14d84995-9793-4051-8da2-70c4da61c765`, including signed Plus proof and no paid-source regressions. Never use the original phone parent, reviewer or a real family for gift testing. Root owns the helper/catalogue/issuance; its reviewed helper is already hosted and the Littles catalogue remains off. No Docker, backups, deletion activation or provider/paid changes.
